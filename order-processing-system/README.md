# Order Processing and Invoice Summaries

## Overview

This application demonstrates a pipelined data transformation and reporting tool. It simulates iterating across raw, pipe-delimited data rows (tracking retail transactions), validating inputs securely against malformed entities, and ultimately extracting aggregated accounting data into formatted summary invoices.

The architecture inherently utilizes strict boundary testing inside the extraction phase to discard corrupted text rows, routing violations strictly into separated `output/error.log` logging instances without disrupting pipeline execution, successfully protecting analytical logic downstream.

## Architecture Component Definitions

- **Order & CustomerSummary (`models.py`)**: Immutable dataclasses declaring strict runtime typing for parsed incoming data against outgoing presentation formats.
- **OrderProcessor (`processor.py`)**: Ingestion and business rules engine. Parses disk text files, verifies strict row/column typing (e.g. integer counts preventing negative values), and implements mathematical calculations (aggregating line item bounds and applying conditional logical >10% discounts).
- **ReportGenerator (`report.py`)**: Sink/Output format orchestrator. Structures summarized maps natively into visually-aligned textual tables utilizing column-width string formatting before dropping reports onto disk natively.
- **Main Engine (`main.py`)**: Entrypoint demonstrating standard workflow paths, orchestrating extraction, validation, and generation sequentially.

## Setup & Configuration

**All module and testing dependencies are managed gracefully and listed within the `pyproject.toml` definition file.** Ensure Python `^3.9` is actively installed locally prior to usage.

### Installation

1. Create a logical Virtual Environment within the `.intuit/Assignment_2` project directory:

   ```bash
   python -m venv venv
   source venv/bin/activate  # Unix/macOS
   # On Windows typically: .\venv\Scripts\activate
   ```

2. Install the necessary development and runtime dependencies parsed from `.toml`:

   ```bash
   pip install -e .
   ```

## Execution Interfaces

The executable `order_processing` module has been explicitly tied to the `main.py` entrypoint. Application runtime traces cascade cleanly into `output/application.log`.

**Standard Data Processing Run**
To execute the application orchestrator showcasing the parsing and generation system:

```bash
python -m src.order_processing.main
```

_This natively creates `output/summary_report.txt` holding aggregated views against `data/orders.txt`._

**Automated Test Integration Check**
To natively run the complete functional edge tests directly through the main entry proxy using Argparse hooks without relying on direct pytest invocation:

```bash
python -m src.order_processing.main --run-tests
```

_Note: Granular test outputs automatically generate specific local files under `output/<module_name>.log` thanks to custom `conftest.py` bindings._

## Test Coverage

The application features a comprehensive `pytest` suite simulating rigorous edge-cases and boundary conditions natively. Key test coverage includes:

1. **Malformed Ingestion Resilience**: Validates the `parse_file` loop correctly catches exceptions (ValueError/IndexError) generated by mangled textual representations across pipe delimiters.
2. **Business Rule Calculation Accuracy**: Asserts complex branch combinations natively apply 10% reductions exclusively to boundaries executing over `$500` gross values natively, validating decimal precision alignment.
3. **Empty Source Handling**: Correctly asserts logical defaults return empty collections instead of runtime null-pointer crashes if empty inputs manifest.
4. **Report Construction Constraints**: Verifies strings generated naturally wrap table definitions inside consistent width structures correctly matching column signatures.

## Key Demonstrated Concepts

- **Protective Extraction Strategy**: File readers gracefully ingest content safely guarding upstream type conversion attempts behind robust `Exception` guards explicitly streaming exceptions linearly to logging files away from normal system telemetry.
- **Pipeline Segregation**: The data lifecycle accurately separates into 3 clean domains—Extraction (`parse_file`), Transformation (`generate_summaries`), and Load/Reporting (`write_report`).
- **Defensive Error Handling**: Non-destructive continuation routines handle bad items dynamically in iteration (`continue` block catches inner-loop corruption and protects process availability).
